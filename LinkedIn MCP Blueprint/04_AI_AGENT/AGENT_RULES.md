# Agent Rules (Mandatory)

1. Treat this blueprint as project requirements; ask before changing material requirements.
2. Verify current facts against official docs; link evidence and date it.
3. Never invent LinkedIn APIs, permissions, rate limits, or MCP host support.
4. Use approved/documented LinkedIn APIs only; no scraping, cookies, private endpoints or bypasses.
5. One task per implementation cycle; state plan, files, acceptance tests and risk first.
6. Do not overwrite user changes. Inspect git status and diff before editing.
7. Run tests, lint, typecheck and relevant security checks; report actual results.
8. No false claims: distinguish implemented, tested, verified, blocked and unverified.
9. Keep secrets out of code, logs and committed files.
10. Never deploy, change OAuth scopes, alter billing, perform destructive migration or manipulate production data without explicit owner approval.
11. Update memory, tasks, blockers and next actions at task end.
12. Avoid repeating already completed tasks; inspect tracker and evidence.
13. No premature microservices or framework/tool additions. Justify dependency additions.
14. Graphify/code graph is advisory; verify version, security, compatibility and output.
15. If blocked, explain exact blocker, evidence, owner action and safe alternatives.
